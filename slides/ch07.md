# 7.1 声纹与相似度

## 声纹：嗓子的“指纹”
!mermaid 1
- 声带、口腔、说话习惯 → 每个人的**声纹**
- 声纹模型把一段录音变成 **192 个数**：声纹向量
- 同一个人的向量靠得近
::: notes
每个人的声带长短厚薄不同，口腔、鼻腔的形状不同，说话的习惯也不同，所以每个人的声音都有自己的特点。熟人打电话，“喂”一声我们就知道是谁。这种能区分不同人的嗓音特征，叫声纹。
人靠耳朵记住声纹，电脑靠一个“声纹模型”。声纹模型读入一段语音（先转成梅尔频谱一类的特征），输出一串固定长度的数字，叫声纹向量。本书用的 CAM++ 模型，不管录音是 2 秒还是 20 秒，都输出 192 个数。
这个模型是怎么学会的？训练时给它看几千个人、几十万段录音，要求它做到：同一个人的录音，输出的向量要靠近；不同人的录音，输出的向量要远离。训练好以后，它就能给从没见过的人也算出向量，这正是声纹能用于“注册新用户”的原因。2018 年提出的 x-vector让这种“神经网络提取声纹向量”的方法成为主流，CAM++ 是它的改进版本之一，由阿里巴巴的 3D-Speaker 团队开源。
用下面的动画“声纹地图”可以看到 45 段录音的声纹向量投到平面上的样子：同一个人的录音聚成一团。
:::

## 两串数字有多像：余弦相似度
- 向量 = 从原点出发的箭头
- **余弦相似度**：只看方向、不看长短，范围 −1 到 1
- 算一算：(1, 2) 和 (2, 4)：方向相同 → **1**
- 实验 7-1：同一人 **0.92—0.94**，不同人 0.33—0.54
::: notes
有了向量，怎样判断两段录音是不是同一个人？要算两个向量“有多像”。声纹最常用的是余弦相似度。
把向量想成从原点出发的一支箭头。两支箭头方向越一致，夹角越小，余弦值就越接近 1；方向垂直，余弦值是 0；方向相反，是 -1。只看方向、不看长短，所以录音音量大小不影响结果。
公式是：
分子叫“点积”（对应位置相乘再相加），分母是两个向量各自的长度。
本书的 `voicelab.embed()` 已经把每个声纹向量“缩放”成长度为 1，这时分母等于 1，余弦相似度就是点积，用 numpy 写成 `a @ b` 一个符号就算完了。
实验 7-1 的实测结果：同一位志愿者的两段录音相似度 0.92—0.94，不同志愿者之间 0.33—0.54。“未知录音”和志愿者 C 的两段录音相似度是 0.91 和 0.90，和其他人都不到 0.5，可以判断是 C 说的。
:::

# 7.3 门槛的取舍

## 说话人确认要一个门槛
- **注册**：本人录几段，向量取平均作模板
- **验证**：新录音和模板比相似度
- 超过门槛 → 是本人
::: notes
“老人专线”的第一步，是说话人确认：老人报了身份（比如拨的是自己登记的号码），系统核验这个声音是不是他本人，回答“是”或“否”。
做法分两步：
门槛定多少，是一个取舍。
:::

## 7.3.2 两种错误

| | 系统说“是本人” | 系统说“不是本人” |
|---|---|---|
| **真的是本人** | ✓ 正确 | ✗ **误拒绝**（本人进不去） |
| **其实是冒充者** | ✗ **误接受**（冒充者进去了） | ✓ 正确 |

::: notes
验证可能犯两种错误：
门槛调高，冒充者更难进来（FAR 下降），但本人也更容易被拒（FRR 上升）；门槛调低则相反。两种错误此消彼长，不可能同时降到很低，除非模型本身更好。实验 7-2 的实测：
把门槛从低往高调，总能找到一个点，让 FAR 正好等于 FRR，这时的错误率叫等错误率（EER）。EER 越低，说明模型把“本人”和“冒充者”分得越开。论文和产品说明里常用 EER 比较声纹模型，CAM++ 在公开测试集上的 EER 不到 1%。
:::

## 误接受率、误拒绝率、等错误率
- **误接受率**（FAR）：冒充者被放行
- **误拒绝率**（FRR）：本人被拒绝
- 门槛高：FAR ↓、FRR ↑
- **等错误率**（EER）：两者相等时，越低模型越好

## 7.3.2 两种错误

| 门槛 | 0.3 | 0.5 | 0.6 | 0.7 | 0.8 | 0.9 |
|---|---|---|---|---|---|---|
| 误接受率 FAR | 90.2% | 13.4% | 3.6% | 0 | 0 | 0 |
| 误拒绝率 FRR | 0 | 0 | 0 | 0 | 0 | 62.5% |


## 门槛要看场景
!sim threshold-errors
- 实验 7-2：门槛 0.68—0.83 时两种错误都是 0
- 换成**电话音质**：本人平均分 0.89 → **0.59**
- 门槛 0.75：误拒绝率 **100%**

## 7.3.3 门槛要看场景

| 场景 | 更怕哪种错误 | 门槛 |
|---|---|---|
| 银行转账、门禁 | 误接受：冒充者进来损失很大 | 偏高，宁可让本人多说一遍 |
| 老人专线自动调出信息 | 误拒绝：老人被拒会很烦；调错信息也有隐私风险 | 适中，并且只调出不敏感的信息，关键操作再人工确认 |
| 会议纪要分人 | 两种错误代价都不大 | 按 EER 附近取 |


# 7.4 三种任务

## 7.4 三种任务：确认、辨认、日志

| 任务 | 问的问题 | 怎么做 | 例子 |
|---|---|---|---|
| **说话人确认** | “你是不是 A？” | 和 A 的模板比，过门槛就是 | 声纹登录、电话银行核验 |
| **说话人辨认** | “你是 A、B、C、D 里的谁？” | 和所有模板比，选最像的（还可以设门槛，都不像就说“不认识”） | 老人专线认出是哪位老人；判断“未知录音”是谁 |
| **说话人日志** | “这段录音里，谁在什么时候说话？” | 先切段，再把声纹相近的段归成一类 | 会议纪要分人、庭审记录、访谈整理 |


## 说话人日志：谁在什么时候说话
!mermaid 2
- 分割 → 声纹 → 聚类
- 只知道“说话人 0、1、2”，**不知道名字**
- 议事会：找出 3 人，7 句中 **6 句**分对
::: notes
同样是用声纹，任务不同，问法不同：
说话人日志比前两个复杂，因为事先不一定知道有几个人、每个人是谁。sherpa-onnx 的做法分三步：
第 ① 步用的是 pyannote 的分割模型，它每隔一小段时间判断“现在有几个人在说话、是不是换人了”。第 ③ 步“聚类”就是把彼此相似度超过门槛的段放进同一组，组数就是人数。如果事先知道人数，也可以直接指定分成几组。
日志只能告诉你“说话人 0、1、2”，不知道他们叫什么。要写成“主持人：……”，还需要一步辨认：拿每一组的声纹和注册过的模板比。实验 7-3 就是把日志、辨认和第 4 章的识别连起来，输出带名字的会议纪要。
实测结果：议事会 51 秒录音、3 个人、7 句话，日志找出 3 个人，7 句话中 6 句的发言人正确。出错的是主持人和李阿姨，两人都是女声。主持人的第二句话被从中间切成两段，前半段分给了李阿姨；最后一句也被分给了李阿姨。如果事先注册过 3 个人的声纹，跳过聚类，直接逐段辨认，7 句全对。
:::

# 7.5 声纹的用途和风险

## 用在哪里
- **身份核验**：电话银行、社保声纹登录
- **会议和访谈**：分人纪要、字幕
- **安全与司法**：反诈、专业机构鉴定
- **个性化服务**：车载语音认出驾驶者

## 合成声音能骗过声纹吗
- **能**，而且越来越容易
- 不到 3 秒参考音克隆：相似度 **0.70**
- 高于实验 7-2“零错误”门槛范围的下限 0.68
- 要配**防伪检测**（ASVspoof 评测）
::: notes
能，而且越来越容易。第 8 章会看到，只要几秒钟的参考录音，就能克隆出一个人的音色。第 8 章的实验 8-2 测过：用不到 3 秒的参考录音克隆的声音，和本人的声纹相似度达到 0.70，已经高于实验 7-2 里“零错误”门槛范围的下限 0.68，门槛定得偏低的系统就会被它骗过。
所以声纹系统需要配一道“防伪检测”：判断这段声音是真人对着麦克风说的，还是合成、转换、录音回放的。国际上有专门的 ASVspoof 挑战赛评测这类检测方法，2024 年的第五届已经包括大量用最新合成和转换技术生成的“深度伪造”语音。对普通用户来说，结论很简单：声纹不能作为大额转账等关键操作的唯一凭证。
:::

## 声纹是敏感个人信息
- 泄露了**不能像密码一样更换**
- 《个人信息保护法》第二十八条：生物识别信息是**敏感个人信息**
- 第二十九条：要取得**单独同意**
- 老人专线：单独告知、只存向量、可撤回可删除
::: notes
声纹能唯一地识别一个人，一旦泄露无法像密码一样更换。《中华人民共和国个人信息保护法》：
落到“老人专线”上，意味着：
书里的实验全部使用合成的“虚拟授权人”，不涉及真人的声纹。如果你用同学的声音做实验，也要先征得同意（第 8 章和附录 D 有授权书模板）。
:::

# 7.6 语音转换

## 语音转换：换一副嗓子
!mermaid 3
- 把“说什么”和“谁在说”**拆开重组**
- kNN-VC：每一小段换成目标人**最像的那一小段**
::: notes
声纹模型只要“谁在说”，识别模型只要“说了什么”。如果能把一段语音拆成这两部分，再把“谁在说”换成另一个人的，就得到了语音转换（也叫变声）：A 说的话，听起来像 C 在说。
kNN-VC 是一种思路特别直观的语音转换方法。它先用一个大模型（WavLM）把语音变成一帧一帧的特征，这些特征里“说了什么”的信息很多；然后把 C 的所有录音也变成特征，组成一个“素材库”。转换时，A 的每一帧，都到 C 的素材库里找最像的 4 帧（k 近邻，k=4），用它们的平均值代替，最后用声码器变回声音。这就像用 C 说过的“音节碎片”，拼出 A 说的内容。C 的素材越多（作者建议 5 分钟左右），拼得越自然。
语音转换和第 8 章的语音克隆很像，区别在于输入：
两者都能“冒用”别人的声音，所以伦理和法律要求是一样的，第 8 章一起讲。
:::

## 7.6 语音转换：换一副嗓子

| | 语音转换 | 语音克隆（零样本合成） |
|---|---|---|
| 输入 | 一段**语音**（A 说的）+ 目标人的录音 | 一段**文字** + 目标人的录音 |
| 保留什么 | A 的语调、节奏、情感 | 由模型自己决定怎么读 |
| 典型用途 | 直播变声、影视配音、保护说话人隐私 | 有声书、导航、智能助手 |


## 前沿视窗
- **声纹和防伪走到一起**
- **“谁说了什么”一步到位**：语音大模型直接输出带说话人标签的转写稿
::: notes
声纹和防伪走到一起。过去声纹识别只回答“是不是这个人”，现在还要回答“是不是真人”。ASVspoof 5 等评测推动了“说话人确认 + 伪造检测”的联合系统，有的手机和银行应用已经要求用户念一串随机数字，同时检测活体和声纹，防止用录音或合成声音冒充。
会议纪要的“谁说了什么”一步到位。传统的做法是本章的“日志 + 识别”两步走。截至 2026 年，越来越多的语音大模型可以直接输出带说话人标签的转写稿，在线会议软件的自动纪要大多已经能区分发言人。不过，对口音重、多人抢话、声音相近的录音，分人仍然是难点，本章实验里两位女声被混淆就是一个缩影。
:::
